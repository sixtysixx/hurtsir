SirHurt leans on runtime libraries that a fresh Windows install often doesn't ship, and its files
look like a hack tool to every antivirus heuristic scanner. Sort both out _before_ the first
launch and you avoid most of the failures people later blame on the injector.

**Stage 1 of 4.**

<Aside type="tip" title="Before you start">

- You need **administrator access** on the machine.
- Allow roughly **2 GB** of free disk space.
- Confirm you're on Windows **24H2 or newer** — run `winver` from the Start menu.

</Aside>

## Step 1 — Give SirHurt its own folder

Every later step (exclusions, cleaning, reinstalling) gets simpler if SirHurt lives somewhere
obvious and predictable.

<Steps>

1. Create a dedicated folder for SirHurt — if you extract an archive with 7-Zip or WinRAR, you can
   normally use the folder the archive already creates.

2. Keep it **out of OneDrive-synced locations** such as Desktop or Documents. Cloud sync can lock
   or "restore" files while you're installing, which produces confusing partial installs. (fuck
   OneDrive ngl)

3. Keep it **out of `C:\Program Files`**. That tree is write-protected, so updates and the Cleaner
   both need elevation just to touch their own files.

</Steps>

## Step 2 — Add antivirus exclusions

This is the single most important step. If your antivirus quarantines SirHurt's files, nothing
downstream will work, and the failure will look random rather than like an antivirus problem.

<Steps>

1. Open your antivirus or Windows Security (**Windows Security → Virus & threat protection →
   Manage settings**).

2. Temporarily switch off **real-time protection** so the next steps aren't interrupted. Windows
   may re-enable this on its own after a while; that's expected.

3. Add a **folder exclusion** for the SirHurt folder you created in step 1.

4. Add a **second folder exclusion** for Roblox itself. Paste the path exactly as written —
   `%LOCALAPPDATA%\Roblox` — into the exclusion box rather than browsing to it, so you don't
   accidentally exclude the wrong profile. Windows expands it to something like
   `C:\Users\<you>\AppData\Local\Roblox`.

5. If anything was previously removed, open **Protection history** and restore the quarantined
   SirHurt files before continuing.

6. Verify the exclusions stuck by opening the exclusions list again and confirming **both** entries
   are present.

</Steps>

<Aside type="danger" title="Exclude folders, not whole drives">
  Only ever exclude the two specific folders above, and don't leave real-time
  protection permanently disabled. Excluding an entire drive or turning
  protection off is a genuine security risk and not something you need
  in order to run SirHurt.
</Aside>

## Step 3 — Repair system files

Corrupt or mismatched Windows component files are a common cause of silent loader crashes. This
chain checks the component store and repairs it from a known-good source, and it stops as soon as
something actually fails instead of reporting success regardless.

<Steps>

1. Open the Start menu, type `PowerShell`, right-click **Windows PowerShell** and choose
   **Run as administrator**.

2. Paste the following and press Enter. It checks the exit code after every command and prints one
   green or red summary line at the end:

   ```powershell
   $failed = $false
   foreach ($step in @(
       @{ Name = "SFC scan";                 Exe = "sfc.exe";  Args = @("/scannow") },
       @{ Name = "DISM CheckHealth";         Exe = "dism.exe"; Args = @("/Online", "/Cleanup-Image", "/CheckHealth") },
       @{ Name = "DISM ScanHealth";          Exe = "dism.exe"; Args = @("/Online", "/Cleanup-Image", "/ScanHealth") },
       @{ Name = "DISM RestoreHealth";       Exe = "dism.exe"; Args = @("/Online", "/Cleanup-Image", "/RestoreHealth") }
   )) {
       Write-Host "==> $($step.Name)" -ForegroundColor Cyan
       & $step.Exe @($step.Args)
       $code = $LASTEXITCODE
       if ($code -notin 0, 3010) {
           Write-Host "FAILED: $($step.Name) exited with code $code" -ForegroundColor Red
           $failed = $true
           break
       }
   }
   if ($failed) { Write-Host "ERROR: System repair chain failed." -ForegroundColor Red }
   else { Write-Host "SUCCESS: System repair chain completed. Reboot before continuing." -ForegroundColor Green }
   ```

3. Let it finish without closing the window. This can take several minutes; the scan pauses at
   different percentages and that is normal.

4. Check the last line. **SUCCESS** means the component store is healthy. Exit code `3010` also
   counts as success — it means the repair worked and a reboot is required. If you get **ERROR**,
   the line above it names the command that failed, which usually points at a disk or permissions
   problem worth fixing before you go further.

5. Reboot once before installing anything else.

</Steps>

## Step 4 — Install the required runtimes

SirHurt will not start without these. Install **both architectures** of the Visual C++
redistributables — a 64-bit Windows install is not a substitute for the x86 package.

<Steps>

1. Download and install the **x86** [Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170#latest-supported-redistributable-version).

2. Download and install the **x64** Visual C++ Redistributable from the same page.

3. Download and install the [.NET SDK — both x86 and x64](https://dotnet.microsoft.com/en-us/download).

4. Use the installers' defaults. There's no need to customise components.

5. **Restart your PC.** The runtimes register themselves during the reboot, so skipping this
   leaves the loader unable to load them.

</Steps>

<Aside type="caution" title="Both architectures, then reboot">
  Installing x64 and not x86 is the most common mistake at this step. Install
  both, then actually reboot rather than just logging out.
</Aside>

## Step 5 — Verify you're ready

Run through this list before moving on. Each item maps to a failure you would otherwise have to
debug later.

<Steps>

1. Your SirHurt folder exists, is outside OneDrive and `C:\Program Files`, and you know its full
   path.

2. **Two** antivirus folder exclusions are listed and confirmed: the SirHurt folder and
   `%LOCALAPPDATA%\Roblox`.

3. The repair chain finished and printed **SUCCESS** (or exited `3010`).

4. Both VC++ redistributables and the .NET SDK are installed.

5. You have rebooted since installing the runtimes.

6. You're on Windows **24H2 or newer**.

</Steps>
