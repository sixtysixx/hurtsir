SirHurt leans on runtime libraries that a fresh Windows install often doesn't ship, and its
files look like a hack tool to every antivirus heuristic scanner. Sort both out _before_ the
first launch and you avoid most of the failures people blame on the injector.

Problems you skip here tend to surface later as "the bootstrapper closes instantly" or "a DLL
is missing" -both are covered on the [Troubleshooting](/guide/troubleshooting/) page.

<Aside type="tip" title="Before you start">
  - You need **administrator access** on the machine. - Allow roughly **2 GB**
  of free disk space. - Confirm you're on Windows **24H2 or newer** -run
  `winver` from the Start menu.
</Aside>

## Step 1 - Give SirHurt its own folder

Every later step (exclusions, cleaning, reinstalling) gets simpler if SirHurt lives somewhere
obvious and predictable.

<Steps>

1. Create a dedicated folder in the root of a drive -for example `C:\Users\USERNAME\Downloads\SuperAwesomeSauceExecutor`.

2. Keep it **out of OneDrive-synced locations** such as Desktop or Documents. Cloud sync can
   lock or "restore" files while you're installing, which produces confusing partial installs.

3. Keep it **out of `C:\Program Files`**. That tree is write-protected, so updates and the
   Cleaner both need elevation just to touch their own files.

4. Note the exact path down -you'll paste it into your antivirus exclusion list in the next
   step.

</Steps>

## Step 2 - Add antivirus exclusions

This is the single most important step. If your antivirus quarantines SirHurt's files, nothing
downstream will work, and the failure will look random rather than like an antivirus problem.

<Steps>

1. Open your antivirus or Windows Security (**Windows Security → Virus & threat protection →
   Manage settings**).

2. Temporarily switch off **real-time protection** so the next steps aren't interrupted. Windows
   may re-enable this on its own after a while; that's expected.

3. Add a **folder exclusion** for the folder you created in step 1 (for example `C:\Users\USERNAME\Downloads\SuperAwesomeSauceExecutor`).

4. If it was previously removed, open **Protection history** and restore the quarantined SirHurt
   files before continuing.

5. Add an exclusion for the **Roblox install directory** as well. The bootstrapper writes there
   when injecting, and a scanner can delete the payload mid-injection.

6. Verify the exclusions stuck by opening the exclusions list again and confirming both entries
   are present.

</Steps>

<Aside type="danger" title="Exclude folders, not whole drives">
  Only ever exclude the specific folders above, and don't leave real-time
  protection permanently disabled. Excluding an entire drive -or turning
  protection off for good -is a genuine security risk and not something you need
  in order to run SirHurt.
</Aside>

## Step 3 - Repair system files

Corrupt or mismatched Windows component files are a common cause of silent bootstrapper
crashes. This chain checks the component store and repairs it from a known-good source.

<Steps>

1. Open the Start menu, type `PowerShell`, right-click **Windows PowerShell** and choose
   **Run as administrator**.

2. Paste the following and press Enter. It runs the full repair chain and prints a green
   success line when everything completes:

   ```powershell
   try { sfc /scannow; DISM /Online /Cleanup-Image /CheckHealth; DISM /Online /Cleanup-Image /ScanHealth; DISM /Online /Cleanup-Image /RestoreHealth; Write-Host -ForegroundColor Green "SUCCESS: System repair chain executed successfully." } catch { Write-Host -ForegroundColor Red "ERROR: System repair chain failed: $_" }
   ```

3. Let it finish without closing the window. This can take several minutes; the scan pauses at
   different percentages and that is normal.

4. Check the last line. **SUCCESS** means the component store is healthy. If you get **ERROR**,
   read the message it prints -a failed repair usually points at a disk or permissions problem
   worth fixing before you go further.

5. Reboot once before installing anything else.

</Steps>

## Step 4 - Install the required runtimes

SirHurt will not start without these. Install **both architectures** of the Visual C++
redistributables -a 64-bit Windows install is not a substitute for the x86 package.

<Steps>

1. Download and install the **x86** [Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170#latest-supported-redistributable-version).

2. Download and install the **x64** Visual C++ Redistributable from the same page.

3. Download and install the [.NET SDK - Both x86 and x64](https://dotnet.microsoft.com/en-us/download) .

4. Use the installers' defaults. There's no need to customise components.

5. **Restart your PC.** The runtimes register themselves during the reboot, so skipping this
   leaves the bootstrapper unable to load them.

</Steps>

<Aside type="caution" title="Both architectures, then reboot">
  Installing x64 and not x86 is the most common mistake at this step. Install
  both, then actually reboot rather than just logging out.
</Aside>

## Step 5 - Verify you're ready

Run through this list before moving on. Each item maps to a failure you would otherwise have to
debug later.

<Steps>

1. Your SirHurt folder exists, and you know its full path.

2. Both antivirus exclusions (SirHurt folder and Roblox directory) are listed and confirmed.

3. The repair chain finished and printed **SUCCESS**.

4. Both VC++ redistributables and the .NET SDK are installed.

5. You have rebooted since installing the runtimes.

6. You're on Windows **24H2 or newer**.

</Steps>

If every box is ticked, continue to [Roblox Settings](/guide/roblox-settings/) to configure
Roblox itself. If something failed, check [Troubleshooting](/guide/troubleshooting/) -the
antivirus and hung-bootstrapper sections cover these exact symptoms.
